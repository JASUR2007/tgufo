## Что ещё исправить
1. **Private не полностью соответствует ТЗ.** В app/api/deps.py пользователь ADMIN получает доступ без разрешения владельца. В ТЗ: private только тем, кому разрешил владелец. Либо убрать исключение, либо получить явное согласование работодателя. Тест сейчас закрепляет именно административное исключение.
2. **Полный access token в URL.** Плеер/картинки передают общий токен аккаунта как ?token=. Он может попасть в access-логи/скопированные ссылки. Лучше отдельный короткоживущий media-ticket с ограничением на конкретное видео либо защищённая cookie. Нельзя считать такое исправление полной финальной проверкой безопасности.
3. **Кеш превью private.** get_thumbnail_response выставляет Cache-Control: public, max-age=86400 для S3-ответа независимо от видимости видео. Для private/hidden нужен private/no-store; авторизация на endpoint не делает публичное кеширование приватного контента безопасным.
4. **Новые thumbnails остаются локальными.** generate_thumbnail пишет только в storage/thumbnails; в process_video_background нет загрузки полученного JPG в S3. Путь чтения сначала ищет S3, затем локальный диск. Если заявляете объектное хранение всех медиа, сохранять превью в S3 и проверить чтение независимо от локальной копии.
5. **S3-ошибки скрываются локальным fallback.** save_file продолжает успешную запись на диск при ошибке put_object. Для демонстрации обязательного объектного хранения нужен явный отказ/ошибка, а не видимость успешного S3. Для Gufo временные файлы ffmpeg допустимы сами по себе, в отличие от строгого stateless ТЗ Invix.
6. **Swagger — отдельная финальная проверка, не подтверждённый дефект.** Реальная схема FastAPI — /api/v1/openapi.json; она должна работать через общий /api/. Отдельный location /openapi.json у nginx лишний/несогласованный, но сам по себе не доказывает поломку Swagger.
7. **Проверка реального сценария.** Доказать регистрация -> upload настоящего MP4 -> завершение обработки -> воспроизведение/перемотка -> лайк -> комментарий, а также private owner/grantee/stranger/moderator. Текущие тесты используют dummy media bytes и не доказывают воспроизведение MP4.
